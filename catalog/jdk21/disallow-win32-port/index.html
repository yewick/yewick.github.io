01 · CONCEPTUAL MODEL

01先抓住核心模型

JDK 21 将 Windows 32 位 x86 端口标记为 deprecated for removal。这个 JEP 不改变主流 64 位 Windows、Linux 或 macOS 平台的 Java 运行方式。

PORT

平台端口

JDK 的端口与特定 CPU 架构、操作系统 ABI 相关。

DEPRECATE

弃用为移除

该标记不会立即删除能力，但意味着后续版本可能不再提供。

MIGRATE

迁移排查

检查 CI、桌面客户端、本地库和安装包是否依赖 32 位 JDK。

  • Windows 32 位 x86 端口被标记为 deprecated for removal。
  • 主流 64 位 Windows x64 与 Arm64 不在本次弃用范围内。
  • 旧平台用户应尽快验证 64 位运行时和依赖链。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

把 x86 和 x64 视为同一平台

32 位与 64 位进程模型、可用地址空间和本地库 ABI 不同。

02WATCH OUT

只检查开发机

还需要检查 CI runner、打包环境和最终用户的运行环境。

04 · SUMMARY

04本章小结

TAKEAWAYS

为移除维护成本高、使用率低的旧平台移植版做准备。

  • 弃用为移除不等于立刻失效。
  • 平台迁移首先是依赖链梳理。
  • 主流 x64 与 Arm64 用户通常不受此项影响。
