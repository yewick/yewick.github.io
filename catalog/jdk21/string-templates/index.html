01 · CONCEPTUAL MODEL

01先抓住核心模型

字符串模板把固定文本与嵌入式表达式组合在一起，再由模板处理器决定最终格式。它比简单拼接更强调可检查性和上下文安全。

TEMPLATE

模板表达式

固定文本与反斜杠包裹的表达式共同组成模板。

PROCESSOR

处理器

STR、FMT 或自定义处理器决定模板如何验证与组合。

PREVIEW

预览特性

JDK 21 中需要开启 preview 才能编译和运行。

  • 嵌入式表达式使用反斜杠加花括号，而不是传统字符串拼接。
  • 模板先形成可处理的结构，再交给模板处理器转换。
  • 标准处理器包括 STR 与 FMT，也允许实现自定义处理器。
02 · HANDS-ON

02构造一条可读的欢迎信息

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

TemplateDemo.java 
record User(String name, int age) {}

public class TemplateDemo {
    public static void main(String[] args) {
        User user = new User("Duke", 21);

        String message = STR."""
            欢迎 \{user.name()}，
            今年 \{user.age()} 岁。
            """;

        System.out.println(message);
    }
}

编译命令：使用 JDK 21 预览能力：javac --enable-preview --release 21 TemplateDemo.java。

不等于字符串拼接：模板处理器可以在生成结果之前检查表达式、格式和上下文，这为 SQL、HTML 等场景提供了安全扩展点。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

省略处理器

模板必须有处理器，例如 STR."..."；它不是无上下文的语言级字符串插值。

02WATCH OUT

把预览语法写进长期 API

预览特性可能调整甚至被撤回，库设计需要谨慎。

04 · SUMMARY

04本章小结

TAKEAWAYS

把插值、格式化和安全处理交给模板处理器。

  • 模板 = 文本 + 表达式 + 处理器。
  • 先组合模板，再决定如何生成结果。
  • JDK 21 中必须明确预览边界。
