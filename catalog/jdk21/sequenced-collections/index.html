01 · CONCEPTUAL MODEL

01先抓住核心模型

JDK 21 引入 SequencedCollection、SequencedSet 和 SequencedMap，用统一接口描述具有确定遇到顺序的集合，并提供首尾访问与反向视图。

LIST

顺序集合

List、Deque 等集合获得统一的 getFirst、getLast 与 reversed。

SET

顺序集

LinkedHashSet 等具有顺序的 Set 可以表达首尾元素。

MAP

顺序映射

LinkedHashMap 等映射可访问首个和最后一个键值对。

  • 新增 SequencedCollection、SequencedSet、SequencedMap 接口。
  • 集合支持 addFirst、addLast、getFirst、getLast 与 removeFirst 等统一操作。
  • reversed() 返回反向顺序视图，而不是复制整个集合。
02 · HANDS-ON

02用统一 API 处理首尾和反向视图

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

SequencedDemo.java 
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;

public class SequencedDemo {
    public static void main(String[] args) {
        List<String> logs = new ArrayList<>(
            List.of("boot", "ready", "serve")
        );

        logs.addFirst("start");
        logs.addLast("stop");

        System.out.println(logs.getFirst());
        System.out.println(logs.getLast());
        System.out.println(logs.reversed());

        var versions = new LinkedHashMap<String, Integer>();
        versions.put("17", 17);
        versions.put("21", 21);
        System.out.println(versions.firstEntry());
        System.out.println(versions.lastEntry());
    }
}

反向视图不是副本：对 reversed() 结果的修改会反映到原集合；遍历和访问规则要依据接口契约。

不是所有集合都有顺序：HashSet 等无序集合不具有确定遇到顺序，因此不自动获得顺序集合语义。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

把顺序误当排序

顺序集合表达的是确定的遇到顺序，不代表元素按自然顺序排序。

02WATCH OUT

替换具体实现

接口统一了能力，但如果业务依赖 LinkedHashMap 的插入顺序，仍应保留明确的实现选择。

04 · SUMMARY

04本章小结

TAKEAWAYS

让“有首尾顺序”的集合拥有统一契约。

  • 首尾访问终于有了统一接口。
  • reversed() 提供视图而非复制。
  • 顺序与排序是两个不同概念。
