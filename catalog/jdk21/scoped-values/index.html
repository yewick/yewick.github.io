01 · CONCEPTUAL MODEL

01先抓住核心模型

ScopedValue 提供在有限动态作用域内共享不可变值的能力。它与虚拟线程和结构化并发配合时，能表达比可变 ThreadLocal 更清晰的上下文生命周期。

BIND

绑定值

ScopedValue.where 在代码块执行期间为键绑定值。

READ

读取值

作用域内通过 get() 读取；作用域外读取会抛出异常。

IMMUTABLE

不可变

作用域内不能修改已绑定值，降低隐式状态泄漏。

  • 新增 ScopedValue API，用于动态作用域上下文。
  • 绑定具有明确开始与结束，不依赖线程复用。
  • 在 JDK 21 中仍为预览特性。
02 · HANDS-ON

02将当前用户绑定到一个调用作用域

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

ScopedValueDemo.java 
public class ScopedValueDemo {
    private static final ScopedValue<String> USER =
        ScopedValue.newInstance();

    public static void main(String[] args) {
        ScopedValue.where(USER, "duke")
            .run(() -> handleRequest());
    }

    static void handleRequest() {
        System.out.println("当前用户: " + USER.get());
    }
}

生命周期更明确：上下文从绑定开始，到 run 或 call 结束；外部代码不能继续读取。

不是所有 ThreadLocal 的一比一替代：可变缓存、线程长期共享对象等场景仍需重新设计。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

把作用域值当缓存

ScopedValue 表达调用上下文，不应承担昂贵资源的线程级缓存。

02WATCH OUT

跨作用域保存值快照

作用域内可以读取但不能修改；需要传递的数据应作为参数或新绑定继续传递。

04本章小结

TAKEAWAYS

把不可变上下文显式限制在调用作用域内。
