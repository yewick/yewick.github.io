01 · CONCEPTUAL MODEL

01先抓住核心模型

记录模式让 instanceof 与 switch 可以直接解构 record。模式可以嵌套，从而用接近数据形状的语法同时完成类型检查与变量绑定。

TYPE

先匹配类型

记录模式首先要求值与记录类型兼容。

COMPONENT

再解构组件

每个组件位置都能继续使用类型模式或嵌套记录模式。

SCOPE

流程敏感作用域

模式变量只在匹配成功的控制流范围内可用。

  • instanceof 可以直接匹配 Record 并提取组件。
  • 记录模式支持任意层级嵌套。
  • 可以与 switch 模式匹配组合使用。
02 · HANDS-ON

02拆解一条二维线段

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

RecordPatternDemo.java 
record Point(int x, int y) {}
record Line(Point start, Point end) {}

public class RecordPatternDemo {
    public static void main(String[] args) {
        Object value = new Line(new Point(1, 2), new Point(8, 9));

        if (value instanceof Line(
                Point(var x1, var y1),
                Point(var x2, var y2))) {
            System.out.printf(
                "从 (%d,%d) 到 (%d,%d)%n",
                x1, y1, x2, y2
            );
        }
    }
}

类型检查与解构同时发生：代码不再需要先强转外层记录，再逐个调用访问器。

模式变量不是全局变量：变量只在模式匹配成功的分支和作用域中可见。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

为了模式而滥用 record

record 适合透明数据载体；具有复杂可变生命周期和身份语义的领域对象仍应按模型设计。

02WATCH OUT

过深的嵌套

嵌套模式很直观，但过多层解构会降低可读性，必要时拆出辅助方法。

04 · SUMMARY

04本章小结

TAKEAWAYS

一次匹配，直接拆开记录中的组件。

  • 记录模式让数据形状直接出现在控制流中。
  • 解构可以嵌套，并保留精确类型。
  • 模式变量遵守流程敏感作用域。
