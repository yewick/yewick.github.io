01 · CONCEPTUAL MODEL

01先抓住核心模型

JDK 21 开始，当 Java Agent 在运行时被动态加载，JVM 会发出警告。这个准备性变化为未来默认禁止动态挂载、提升启动完整性做准备。

STARTUP

启动时加载

通过 -javaagent 在 JVM 启动阶段加载，行为更可预测。

DYNAMIC

动态挂载

程序启动后通过 Attach API 等机制挂载 Agent。

WARNING

显式选择

JDK 21 用警告提示未来治理方向，并允许临时显式放行。

  • 运行时动态加载 Agent 时 JVM 输出 warning。
  • 可临时使用 -XX:+EnableDynamicAgentLoading 显式允许。
  • 启动时通过 -javaagent 配置的 Agent 不触发该动态加载警告。
02 · HANDS-ON

02识别并显式选择

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

agent-policy.sh 
# JDK 21 可能输出：
# WARNING: A Java agent has been loaded dynamically

# 仅为兼容既有工具时显式放行
java -XX:+EnableDynamicAgentLoading \
     -jar application.jar

先确认是谁在挂载：警告可能来自 APM、调试、热部署或测试工具；先定位来源再讨论策略。

显式放行不是长期默认方案：该开关用于迁移期兼容，不应无脑加入所有生产启动脚本。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

误以为 Agent 已不可用

JDK 21 主要是警告和准备性变化，并未立即默认禁止。

02WATCH OUT

忽略供应链风险

动态 Agent 能修改字节码和运行时行为，需要受控来源和审计。

04 · SUMMARY

04本章小结

TAKEAWAYS

让运行时动态挂载 Agent 从默认行为变成显式选择。

  • 动态 Agent 加载正在变成需要显式声明的行为。
  • 启动加载比运行时挂载更容易审计。
  • 迁移期开关应只为可识别工具保留。
