01 · CONCEPTUAL MODEL

01先抓住核心模型

Vector API 让 Java 代码用 Vector 类型描述批量元素运算，运行时再映射到可用硬件指令。它是性能实验 API，而不是普通集合替代品。

SPECIES

向量形状

VectorSpecies 描述元素类型、lane 数量与形状。

LANE

并行元素

一次运算同时处理多个 lane，最终由运行时映射到硬件。

TAIL

尾部处理

数组长度不一定整除向量宽度，剩余元素仍需标量代码。

  • jdk.incubator.vector 提供元素类型专用的向量 API。
  • 可组合向量运算、掩码和数组加载/存储。
  • JDK 21 中是第六轮孵化 API。
02 · HANDS-ON

02一次计算四个 float 的和

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

VectorDemo.java 
import jdk.incubator.vector.FloatVector;
import jdk.incubator.vector.VectorSpecies;

public class VectorDemo {
    static final VectorSpecies<Float> SPECIES =
        FloatVector.SPECIES_128;

    public static void main(String[] args) {
        float[] left = {1, 2, 3, 4};
        float[] right = {10, 20, 30, 40};
        float[] result = new float[4];

        FloatVector a = FloatVector.fromArray(SPECIES, left, 0);
        FloatVector b = FloatVector.fromArray(SPECIES, right, 0);
        a.add(b).intoArray(result, 0);

        System.out.println(java.util.Arrays.toString(result));
    }
}

编译与运行：需要 --enable-preview --release 21，并通过 --add-modules jdk.incubator.vector 引入孵化模块。

不要先优化再测量：向量 API 是否产生硬件优势取决于元素类型、数据规模和 JVM 映射；应以基准测试为准。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

忘记尾部

实际数组长度往往不是 species length 的整数倍，必须处理剩余元素。

02WATCH OUT

把孵化和稳定 API 混用

孵化模块的 API 和包路径可能随版本调整，应隔离在性能关键层。

04 · SUMMARY

04本章小结

TAKEAWAYS

用可移植的向量表达式描述数据并行。

  • 向量 API 描述数据并行，而非线程并行。
  • 向量形状与尾部处理是核心细节。
  • 所有收益都必须用基准测试确认。
