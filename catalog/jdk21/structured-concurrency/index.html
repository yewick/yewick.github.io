01 · CONCEPTUAL MODEL

01先抓住核心模型

结构化并发把同一业务操作拆出的多个并发子任务组织到 StructuredTaskScope 中。父作用域统一等待、取消和传播错误，使线程关系与调用结构保持一致。

SCOPE

共同作用域

所有 fork 出的子任务都属于同一个词法作用域。

JOIN

统一汇合

join 等待子任务结束，或按策略在失败时关闭剩余任务。

VIRTUAL

默认运行于虚拟线程

结构化并发提供任务组织模型，虚拟线程提供执行载体。

  • StructuredTaskScope 作为预览 API 出现在 JDK 21。
  • ShutdownOnFailure 在任一子任务失败时可取消其他任务。
  • 作用域关闭时不会留下未受管理的并发任务。
02 · HANDS-ON

02并发查询用户与订单后组合结果

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

StructuredDemo.java 
import java.util.concurrent.StructuredTaskScope;

public class StructuredDemo {
    record Profile(String user, String orders) {}

    static Profile loadProfile(long id) throws Exception {
        try (var scope =
                 new StructuredTaskScope.ShutdownOnFailure()) {
            var user = scope.fork(() -> findUser(id));
            var orders = scope.fork(() -> findOrders(id));

            scope.join().throwIfFailed();
            return new Profile(user.get(), orders.get());
        }
    }

    static String findUser(long id) {
        return "user-" + id;
    }

    static String findOrders(long id) {
        return "orders-" + id;
    }

    public static void main(String[] args) throws Exception {
        System.out.println(loadProfile(21));
    }
}

组织关系比执行方式更重要：结构化并发主要解决子任务生命周期与错误传播；虚拟线程解决大量任务的执行成本。

仍然是预览 API：JDK 21 中 API 可能变化，需要 --enable-preview 才能编译运行。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

把 fork 当线程池

作用域表示一次业务操作的子任务边界，不应被长期持有或跨请求复用。

02WATCH OUT

失败后继续读取结果

ShutdownOnFailure 会取消其他任务；应先 join 并检查失败，再读取成功结果。

04 · SUMMARY

04本章小结

TAKEAWAYS

让一组并发子任务拥有共同的开始、结束与错误边界。

  • 子任务不应逃逸出父操作作用域。
  • 失败和取消应沿结构化边界传播。
  • 结构化并发与虚拟线程是互补能力。
