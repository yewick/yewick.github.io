01 · CONCEPTUAL MODEL

01先抓住核心模型

未命名模式与未命名变量用下划线代替不会被使用的名字，让模式解构和局部变量声明更直接，同时避免无意义的命名与未使用警告。

_

未命名模式

模式位置上的下划线表示不绑定该位置的值。

LOCAL

未命名变量

局部变量或异常参数可以省略名字，明确表达不会读取这个值。

SCOPE

不可访问

未命名变量没有可用的标识符，不能像普通变量一样引用。

  • 记录模式中的组件可以使用未命名模式。
  • 局部变量声明、for-each 与 catch 参数可使用未命名变量。
  • 编译器不再因为“变量定义了但未使用”而需要无意义命名。
02 · HANDS-ON

02只关心坐标 x，忽略 y

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

UnnamedPatternDemo.java 
record Point(int x, int y) {}
record Box<T>(T value) {}

public class UnnamedPatternDemo {
    public static void main(String[] args) {
        Object value = new Point(12, 8);

        if (value instanceof Point(var x, _)) {
            System.out.println("x = " + x);
        }

        Object box = new Box<>("payload");
        if (box instanceof Box(_)) {
            System.out.println("只关心是否是非 null Box");
        }

        try {
            Integer.parseInt("not-a-number");
        } catch (NumberFormatException _) {
            System.out.println("格式错误");
        }
    }
}

意图更明确：下划线不是约等于“丢弃赋值”，而是语言层面声明“此处不需要名字”。

预览边界：JDK 21 编译该语法需要启用 preview。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

把 _ 当成普通变量

未命名变量不能被读取，也不能通过多个下划线规避命名。

02WATCH OUT

过度使用

省略名字应当强化意图；如果值确实需要理解，保留描述性变量名更好。

TAKEAWAYS
