01 · CONCEPTUAL MODEL

01先抓住核心模型

switch 现在可以使用类型模式、记录模式和守卫条件 when。对于 sealed 类型，编译器还能检查分支是否穷尽。

TYPE

类型模式

每个 case 可绑定具体的运行时类型及其变量。

WHEN

守卫条件

类型匹配后再检查附加布尔条件，失败则继续尝试后续分支。

SEALED

穷尽性

封闭类型层级让编译器能确认所有可能子类型都被覆盖。

  • case 支持带变量的类型模式。
  • case 可与记录模式组合，直接解构数据。
  • when 守卫允许更精确的分支选择，sealed 层级支持穷尽性检查。
02 · HANDS-ON

02按 sealed 形状计算面积

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

SwitchPatternDemo.java 
sealed interface Shape
    permits Circle, Rectangle {}

record Circle(double radius) implements Shape {}
record Rectangle(double width, double height)
    implements Shape {}

public class SwitchPatternDemo {
    static double area(Shape shape) {
        return switch (shape) {
            case Circle(var r) ->
                Math.PI * r * r;
            case Rectangle(var w, var h) when w > 0 && h > 0 ->
                w * h;
            case Rectangle ignored ->
                throw new IllegalArgumentException("尺寸必须为正");
        };
    }

    public static void main(String[] args) {
        System.out.println(area(new Circle(2)));
    }
}

穷尽性是编译期能力：sealed 类型没有 default 也可以完成穷尽性检查，新增子类型时编译器会提示需要处理的分支。

模式顺序有语义：更具体的类型和带 when 的分支通常应放在更宽泛的分支之前。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

遗漏 domineering 模式

过宽的模式会让后续分支不可达，编译器会拒绝这类 switch。

02WATCH OUT

把 null 当普通模式值

null 的匹配规则需要单独理解；必要时使用 case null 明确处理。

04本章小结

TAKEAWAYS

让 switch 按类型、组件和条件表达规则。

  • switch 从值分支升级为规则分支。
  • when 让类型匹配再叠加业务条件。
  • sealed 与模式匹配共同提供穷尽性检查。
