01 · CONCEPTUAL MODEL

01先抓住核心模型

JDK 21 的分代 ZGC 将堆区分为年轻代与老年代，分别执行回收。它延续并发、低暂停的设计，同时更适配大多数对象很快死亡的分配模式。

YOUNG

年轻代

频繁回收生命周期短的对象，降低整体复制与扫描成本。

OLD

老年代

承载长期存活对象，回收频率通常更低。

PAUSE

低暂停

分代并不放弃 ZGC 的低延迟目标，仍需按真实负载观察。

  • ZGC 支持年轻代与老年代两套回收策略。
  • JDK 21 中通过 -XX:+ZGenerational 启用分代模式。
  • 默认并启用 ZGC 时，JDK 21 仍要求显式开启分代选项。
02 · HANDS-ON

02用分代 ZGC 启动应用

示例保持最小可读，重点是展示这项能力如何使用，以及它与普通 Java 代码的关系。

start.sh 
java \
  -XX:+UseZGC \
  -XX:+ZGenerational \
  -Xmx8g \
  -Xlog:gc*:file=gc.log \
  -jar app.jar

以日志为准：重点观察 Pause、young generation、old generation、堆占用与 GC 线程 CPU 成本。

不是通用性能开关：GC 选择应由对象生命周期、堆规模、延迟目标与机器资源共同决定。

03 · BOUNDARIES

03工程中的边界与易错点

能写出示例不代表可以安全迁移。下面两个问题最值得在设计和评审阶段确认。

01WATCH OUT

只看平均暂停

尾延迟、CPU 占用和分配速率同样关键，平均值可能掩盖长尾。

02WATCH OUT

未设置明确堆预算

分代回收仍需要足够堆空间；参数组合应在真实压测中验证。

04 · SUMMARY

04本章小结

TAKEAWAYS

在低暂停目标下，利用分代假设提高分配友好度。

  • 分代利用“大多数对象很快死亡”的经验。
  • JDK 21 用 ZGenerational 显式启用。
  • GC 优化必须由日志和压测驱动。
